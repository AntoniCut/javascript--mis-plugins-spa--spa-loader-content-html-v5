# Demos backend: validación PHP y CRUD Node + Express

- **Objetivo**: agregar dos páginas de demo al SPA: una que ejecute funcionalidad PHP en el servidor (validación de formulario vía PHP-FPM/php-cgi) y otra que consuma un CRUD REST de tareas en memoria servido por Node + Express.
- **Rama**: `feat/demos-backend-php-express`
- **Entrega**: work-unit commits en la rama de feature; sin push ni PR salvo pedido explícito del usuario.
- **Test runner**: no hay suite (`pnpm test` es placeholder). Excepción ODD: `php -l`, `node --check`, batería de `curl` determinística contra dev server y API standalone, `pnpm build`, `pnpm preview` y differential check contra el commit base.

## Specs

- **S1** — Página `php-page` (`route id: phpPage`, path `php-page`): demuestra **validación de formulario en el servidor**. Archivos: `src/pages/php/php-page.html`, `src/pages-components/php/php-description.html`, `src/pages-components/php/php-demo.html`, `src/scss/pages/php-page.scss`, `src/scripts/js/pages/php-page.cjs.js`, `src/scripts/js/pages/php-page.esm.js`, `src/routes/route-php-page.js`, `assets/favicon/php-icon.svg`. Título `PHP — Validación en el servidor`. El ESM envía `POST app/services/php/validate.php` con JSON, pinta errores por campo con `textContent`, muestra el código HTTP y, en éxito, los datos normalizados, `serverTime` y `runtime`.
- **S2** — Endpoint `src/services/php/validate.php`: solo `POST` (otro método → `405` con `Allow: POST` y `{"ok":false,"message":"Solo se admite POST."}`); body JSON máx. 16 KB (JSON inválido o no-objeto → `400` con `"La petición no es un JSON válido."`); campos `name` (2–60), `email` (`FILTER_VALIDATE_EMAIL`) y `message` (10–500); errores por campo → `422` `{"ok":false,"message":"Revisá los campos marcados.","errors":{...}}`; éxito → `200` `{"ok":true,"message":"El servidor validó y normalizó los datos.","data":{"name","email","message"},"serverTime":"<ISO-8601>","runtime":"PHP <PHP_VERSION>"}`. Normaliza con `trim`, colapsa espacios y elimina caracteres de control; no usa base de datos, `.env` ni dependencias. Mensajes exactos: `"Escribe tu nombre."`, `"El nombre debe tener entre 2 y 60 caracteres."`, `"Escribe tu correo."`, `"El correo no tiene un formato válido."`, `"Escribe tu mensaje."`, `"El mensaje debe tener entre 10 y 500 caracteres."`.
- **S3** — Página `express-page` (`route id: expressPage`, path `express-page`): demuestra un **CRUD REST de tareas en memoria** servido por Express. Archivos: `src/pages/express/express-page.html`, `src/pages-components/express/express-description.html`, `src/pages-components/express/express-demo.html`, `src/scss/pages/express-page.scss`, `src/scripts/js/pages/express-page.cjs.js`, `src/scripts/js/pages/express-page.esm.js`, `src/routes/route-express-page.js`, `assets/favicon/express-icon.svg`. Título `Express — API de tareas en memoria`. El ESM lista, crea y elimina tareas contra `/api/tasks`, pinta el código HTTP y la latencia leída de `X-Response-Time`, y advierte que los datos se reinician con el proceso.
- **S4** — Router `api/src/tasks-router.js` que exporta `createTasksRouter()`: datos en memoria con ids numéricos autoincrementales y 3 tareas semilla. Contrato: `GET /tasks` → `200 {"ok":true,"tasks":[{"id","title","createdAt"}],"count","message"}`; `POST /tasks` (`express.json({limit:'4kb'})`, `title` string 3–80) → `201` con la tarea; `422 {"ok":false,"message":"Revisá los campos marcados.","errors":{"title":"..."}}`; `DELETE /tasks/:id` → `200 {"ok":true,"deletedId","message"}`, id inexistente → `404 {"ok":false,"message":"La tarea no existe."}`, id no numérico → `400 {"ok":false,"message":"El identificador no es válido."}`. Otro método en cada path → `405` con `Allow`. Middleware de logging (`[tasks] <METHOD> <path> <status> <ms>`) y cabecera `X-Response-Time`. Body inválido → `400`, body > 4 KB → `413`. Montado en `api/src/server.js` (raíz, antes del handler de errores) y en `server/dev-server.js` (`/api`, después de `createApiRouter()`); URL pública idéntica en dev y prod: `/api/tasks`.
- **S5** — Wiring compartido: entradas `phpPage` y `expressPage` en `src/routes/route-manifest.js`; enlaces `PHP` y `Express` en `src/components/layouts/layout-navbar.html` y `src/components/layouts/layout-footer.html`; claves `services` y `apiSource` en `src/routes/paths.js`; soporte `php` en `mapLang()` de `generate-markdown-shiki.js` y en el JSDoc de `types/route.d.js`.
- **S6** — Bloques Shiki: cada ruta declara 6 entradas (html, css, scss, cjs, esm y el fuente del backend: `validate.php` / `tasks-router.js`); los HTML generados en `src/markdown-shiki/pages/php/` y `src/markdown-shiki/pages/express/` se versionan.
- **S7** — Documentación: `README.md` (tabla del API con las rutas de tareas), `specs/arquitectura/01-servicios-backend-arquitectura.md` (inventario con los endpoints nuevos) y este documento con la evidencia de commits.
