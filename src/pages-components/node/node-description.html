API MySQL sobre Express en producción

Node 24 corre el mismo router en el servidor de desarrollo y en producción, detrás de nginx en /api. El proceso lo gestiona systemd como javascript-node.

Esta página envía la sentencia a /api/mysql/query con una URL absoluta desde la raíz del dominio, así que funciona igual en local y en el VPS. En producción no hay CORS: mismo origen.

Qué aporta este runtime

Una sola implementación

El handler de MySQL vive en api/ y lo comparten el dev server y el API de producción.

Solo lectura

SELECT, SHOW, DESCRIBE y EXPLAIN. Las escrituras se rechazan con 400 y otro método con 405.

Health sin MySQL

GET /api/health confirma que el proceso responde, aunque la base esté caída.
